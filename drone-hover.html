Vision-Guided Drone Hover

A simulated quadcopter takes off, detects an ArUco marker through a downward camera, and uses image error as feedback to align above it while holding a target height.

ROS 2 · Ignition Gazebo · OpenCV

Visual servoingArUcoProportional controlUAV

See the hover controller

Demonstration linked from the public repository. The behaviour is takeoff, marker acquisition, alignment, and hover in simulation; it does not include landing. Watch on YouTube ↗
02

Control loop

01 / OBSERVE

Measure height

A downward range sensor reports altitude. The controller compares it with a 1 m target height.

02 / DETECT

Find the marker

OpenCV detects an ArUco marker in the downward camera frame and estimates its image centre.

03 / COMPUTE

Form feedback error

The difference between marker centre and image centre becomes the horizontal alignment error.

04 / COMMAND

Adjust velocity

Proportional feedback produces bounded horizontal and vertical velocity commands, then repeats.

Why vision feedback?

Camera coordinates give a direct signal for centring above a visible target. The controller uses the marker only when detected and after the drone rises above its initial takeoff height.

What I implemented

The ROS 2 controller subscribes to camera and range data, runs marker detection, computes image-plane error, and publishes velocity commands. The public repository includes the Gazebo world and launch instructions.

03

Evidence and limits

This is a proportional hover controller in simulation, shown in one demonstration video. The implementation does not contain a landing phase, obstacle avoidance, or a formal safety guarantee. It is a compact example of closing the loop between camera perception and UAV control.

Review the public ROS 2 repository for the controller and simulation setup.
